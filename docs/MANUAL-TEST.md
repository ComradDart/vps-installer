# Ручная проверка на тестовой VPS

Проверьте отдельно Debian 12, Debian 13, Ubuntu 24.04/26.04 LTS. Нужны snapshot и консоль
провайдера. Эти проверки в песочнице не выполнялись.

1. Подготовьте A-запись домена на VPS, без origin AAAA, DNS only в Cloudflare.
2. Запустите установщик и выберите новый SSH-порт. Проверьте обе новые key-сессии
   и sudo, не закрывая первую. После lockdown root/password/keyboard-interactive
   должны отвергаться; `sshd -t` и effective `sshd -T -C` должны подтверждать настройки.
3. Отдельно испытайте таймер: не подтверждайте SSH gate, подождите 10 минут и
   проверьте восстановление старого доступа. Для Ubuntu проверьте ssh.socket.
4. Проверьте снаружи SSH, HTTP/HTTPS; 2053/8443 и невыбранные TCP/UDP закрыты.
   Просмотрите реальные Docker PortBindings, UFW и DOCKER-USER, включая IPv6 хоста.
5. Проверьте сайт, настоящий сертификат/цепочку/hostname/TLS/HTTP2 и renew --dry-run.
   Перезагрузите VPS: контейнеры, jail sshd, guard, backup и renew timers возвращаются.
6. Через SSH-туннель войдите в панель с выбранными credentials. Внешний доступ к
   панели должен отсутствовать. Проверьте автоматически созданный VLESS-inbound,
   стабильный UUID, профиль --show-client и настоящее подключение с устройства.
   Для Cloudflare включите Proxied, Full (strict), Network → gRPC On; установщик
   должен проверить реальный клиентский маршрут, а не только сайт.
7. Измените сайт, повторите установку: изменения и пароль сохранены. --reconfigure
   должен запросить согласие перед заменой управляемых файлов сайта.
8. Сбросьте пароль отдельной командой: старый вход отклонён, новый работает,
   DB/settings сохранены. 2FA не сбрасывается. Секретов нет в Docker metadata/logs.
9. Создайте backup, измените тестовые настройки/сайт, выполните --restore того же
   identity. Проверьте панель, сайт, TLS и сохранённое предыдущее дерево.
10. Испытайте --uninstall на тестовой VPS: отмена ничего не удаляет; после YES
    контейнеры/units убраны, данные/SSH/пользователь/backups/legacy остаются.

| Отрицательный сценарий | Ожидается |
|---|---|
| Неверный домен/порт/ключ | отказ до lockdown |
| DNS неверен / AAAA не обслуживается | отказ ACME, HTTP nginx остаётся |
| 443/80 занят, включая Docker без docker-proxy | отказ без остановки чужого сервиса |
| Нет диска / Docker / GHCR | отказ без удаления данных |
| ACME не выдал сертификат | нет TLS config с отсутствующими файлами |
| Прерывание SSH gate | rollback drop-in, старые firewall rules сохранены |
| Прерывание reset | возврат snapshot DB и запуск xui |
| Частичная установка | продолжение saved identity; не перегенерировать существующего user |
| Неполная БД без user | не запускать сервер до явной инициализации выбранных credentials |
| Подменённый/повреждённый backup | отказ до live restore |

Для каждого пункта фиксируйте PASSED / FAILED / NOT RUN / MANUAL. Передавайте ошибки
и безопасный --status, без паролей, private keys или полной БД.

Дополнительные проверки транспорта на VPS:

- Повторите --configure-xray: тот же inbound id/UUID, пароль панели не меняется.
- В gRPC у публичного 443 единственный владелец nginx, TCP/10000 снаружи закрыт.
- В REALITY публичный 443 принадлежит только Xray; HTTPS-сайт остаётся доступен
  через self-steal, target nginx:8443 доступен из Xray с правильным SNI.
- Отключите Cloudflare gRPC: настоящий внешний VLESS-сеанс должен упасть; простой
  HTTP 200 не должен превратить результат в PASSED.
- Для relay предоставьте неверный OUTBOUND: локальная маршрутизация не меняется.
  После рабочего подключения остановите OUTBOUND: direct fallback отсутствует.
- Прервите --configure-xray после записи API и после замены Compose. Повторный
  запуск должен восстановить предыдущие файлы/собственные API-изменения и тот же UUID.
- Проверьте /opt/vps-installer/automation-report.json и root-only права secrets/clients.
