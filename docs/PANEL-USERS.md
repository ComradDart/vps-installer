# Индивидуальные SSH-ключи для общей панели

Точка входа: `sudo ./install.sh --panel-users`. Нужна существующая `state.json`
установщика; команда одинаково работает для INBOUND и OUTBOUND. Docker и API 3x-ui
не вызываются, новые административные аккаунты панели не создаются.

## Файлы и ограничения

- `/opt/vps-installer/panel-users.json` — root-only список созданных имён, UID,
  публичных ключей и статуса. Произвольные существующие аккаунты не импортируются.
- `/etc/ssh/vps-panel-keys/ИМЯ` — публичные ключи, изменяемые только root.
  Каталог 0755 и файлы 0644 нужны sshd для чтения после смены UID; секретов здесь нет.
- `/etc/ssh/vps-panel-users.conf` — отдельный `Match User` для каждого аккаунта.
  Управляемый Include добавляется в КОНЕЦ sshd_config: ранний drop-in с Match мог бы
  сделать последующие глобальные директивы основной конфигурации недопустимыми.

`AllowTcpForwarding local`, `PermitOpen 127.0.0.1:2053` и `PermitListen none`
разрешают только нужный direct-tcpip. `MaxSessions 0` запрещает создание session
channel, включая exec, shell и subsystem/SFTP, сохраняя `ssh -N`. Дополнительно
заданы `ForceCommand /bin/false`, shell nologin, `PermitTTY no`, запрет agent,
X11, Unix-socket forwarding, tun и пользовательского rc. Ключи имеют
`restrict,port-forwarding,permitopen="127.0.0.1:2053"`.

Допускается только аутентификация открытым ключом. Внешний AuthorizedKeysCommand
для этих пользователей отключён; сертификатные алгоритмы исключены, чтобы глобальный
TrustedUserCAKeys не позволял обходить отдельный список ключей. RSA использует SHA-2.
Аккаунт получает случайный пароль, от которого сохраняется только hash, а исходное
значение сразу отбрасывается. Это допускает key login на системах без PAM; SSH-вход
по паролю запрещён. Пользователь не получает дополнительных групп; наличие sudo-прав
проверяется перед активацией. Сначала аккаунт просрочен, а активируется лишь после
проверки и reload безопасной политики.

Имеющиеся ограничения Allow/DenyUsers/Groups автоматически не переписываются:
операция останавливается для ручного согласования такой конфигурации.

## Применение и откат

Перед изменением сохраняются main config, отдельная политика, реестр и key-файлы
в `/opt/vps-installer/panel-users-backups/СЛУЧАЙНЫЙ_ID`, включая manifest.json.
Текущий журнал — `panel-users-transaction.json`. Сначала запускается отдельный
systemd-таймер отката через 120 секунд, затем применяется изменение.

Проверки: `sshd -t`, точные эффективные ограничения гостей через `sshd -T -C`,
неизменность эффективных настроек основного администратора и root. Проверяются
loopback, тестовый внешний адрес и текущий адрес SSH-клиента. Более ранний Match,
перекрывающий ограничение, приводит к откату. Используется только reload ssh/sshd;
ssh.socket и существующие подключения основного администратора не перезапускаются.

При ошибке восстанавливаются сохранённые файлы, конфигурация проверяется и
перезагружается. Таймер защищает также от аварийного завершения процесса.
После успешного применения журнал удаляется, таймер отменяется. Резервные копии
остаются. Печатавшаяся команда rollback предназначена для **незавершённой** операции;
после её успешного завершения она ничего не меняет. UID проверяется перед
удалением/завершением процессов, чтобы не затронуть другой аккаунт при повторном
использовании имени.

Отзыв сначала просрочивает аккаунт и очищает его root-controlled ключи, затем
завершает процессы этого UID (TERM, при необходимости KILL) и удаляет аккаунт.
При неудаче очистки доступ остаётся отозванным: откат не восстанавливает ключи.
После удаления может остаться безопасный Match для отсутствующего пользователя;
следующее успешное изменение меню уберёт его. Основной администратор и root
не могут быть выбраны для удаления этим механизмом.

Если отзыв прервался после удаления OS-аккаунта, а запись осталась в реестре,
не назначайте его прежний UID другому пользователю до проверки состояния.
Для проверки оставшихся сессий используйте `pgrep -a -u ИМЯ`, а не общий pkill sshd.

## Проверка в отдельном контейнере

```bash
bash scripts/test_panel_ssh.sh
```

Требуются Docker и доступ к Alpine package repositories. Образ — `alpine:latest`.
Тест не публикует SSH в интернет и создаёт настоящих пользователей только внутри
одноразового контейнера. Выполняется настоящий OpenSSH key login, HTTP-передача
через разрешённый туннель, запреты exec/PTY/SFTP/SCP/другого target/reverse,
замена ключей, отзыв активного туннеля и сохранение primary admin SSH.
Проверяется откат синтаксической ошибки и более раннего Match.

В контейнере нет systemd: его таймер **NOT RUN**, методы проверки/reload используют
настоящий sshd с SIGHUP. Проверка на Debian/Ubuntu VPS с PAM/systemd отдельно
**NOT RUN**. Эти ограничения не подменяются результатом контейнерного теста.
